# MEMORY.md

Decisions, patterns and constraints for the Azure Cost Manager plugin. This file
describes only this repository (`ADR-023`).

Format: `- **[date] Rule.** Reason.` Append; correct an entry by superseding it.

## Decisions

- **[2026-10-16] Azure Cost Management API, signed in with the operator's `az login`.** No secret stored; the plugin sees exactly the billing accounts the operator sees in the portal, and an expired sign-in is reported, not retried.
- **[2026-10-16] Display first, store later.** Phase 1 only shows consumption. Vault notes and raw data are written once a billing account is linked to an Entities Customer (Phase 2), because Azure's account name often differs from the Customer's.
- **[2026-10-16] Vault notes will be written directly**, as `sb-plugins-action-center` does -- the Plugin API has no vault write (operator's choice over adding one).
- **[2026-10-16] Questions are answered through an ADR-032 Workflow** installed from this plugin's Settings: an `.sbf` through the framework's artifact import for now, a Plugin API layer for Hermes content later.

- **[2026-10-16] A customer is a group of enrollments, synced into local data weekly.** One enrollment per customer was wrong on first contact: one customer was a parent plus two linked enrollments, and another's consumption moved to a new enrollment mid-year, so the old one read zero. Pages read local data only; a weekly Hermes cron job calls the sync route. *Supersedes the display-only, refresh-on-open model of 0.1.x.*
- **[2026-10-16] The signed value is entered by the operator.** Indirect EA shows no prepayment and the commitment lots answer 401 to a partner's sign-in, so Azure cannot say what the customer signed for.

- **[2026-10-17] An affiliate's MACC is carved out of its parent's.** A group signs one MACC; each affiliate signs its own fixed MACC that counts against the parent's, and every affiliate dollar burns both. Modelled as parent and affiliate customers, one level deep; the parent rolls everything up and shows allocated, unallocated and over-allocated.

- **[2026-10-17] Every billing profile is synced lightly; customers fully.** The Marketplace report has to cover every buyer, so profiles in no customer get each month's invoice totals and Marketplace charges through the Consumption API, never Cost Management (its per-sign-in throttling makes 135 profiles a matter of days). A profile that leaves a customer keeps those, and loses only the breakdowns.

- **[2026-10-17] Reports first, then the customer.** The landing page is a catalogue of reports; a per-customer report asks for the customer (groups with their affiliates under them) before it shows anything. Operator's navigation, over the 0.6 single page with a customer picker. Old `?customer=&tab=` links redirect.

- **[2026-10-17] A linked customer's signed value lives on its Customer note** (`macc_*` properties, through `entities.customers` `commitment`/`set_commitment`, Entities 1.3+). The operator chose the vault as its single source of truth, so it is editable in Obsidian and visible to the vault. This plugin's data keeps it only for unlinked customers or an older Entities; a note that has one always wins over a value held here. *Supersedes, for linked customers, "the signed value is entered by the operator" being stored here.*

- **[2026-10-17] FinOps findings are one engine with two views.** The Customer view filters the same analysis on the server (today: no forecast scenarios), never a second analysis and never a browser-side hide, so the two cannot disagree and an export cannot leak what the view leaves out.

- **[2026-10-18] Services other plugins depend on: `azure-cost-manager.portfolio` (Entities' Accounts page) and `azure-cost-manager.consumption` (Core42 Insight, own enrollments only, run-rate forecast).** Extend their shapes, never reshape them.
- **[2026-10-17] Other plugins read this one through `azure-cost-manager.portfolio`** (`for_entity(customer_stem)`), never its HTTP routes. Its shape is the portfolio row plus `route`; changing it breaks Entities' customer page, so extend it, do not reshape it.

## Patterns

- **[2026-10-16] The current month is never evidence.** It is partial: no month-over-month change, no run rate, no anomaly is computed from it.
- **[2026-10-16] An anomaly must be sharp and material**: at least 50% off its trailing three-month baseline and at least 2% of the month's total.
- **[2026-10-16] Charts are SVG drawn in the plugin.** The host has no chart library, and a screen may not bring one. *Superseded below.*
- **[2026-10-16] Charts are the host's `echarts`, imported piece by piece** (framework_api 8, `ADR-039`): `echarts/core` plus the chart types and components used, through `echarts-for-react/esm/core`. A canvas cannot resolve CSS variables, so colours are read from the stylesheet when a chart renders.

- **[2026-10-17] A link into Settings carries `back`** (`settingsLink`). Settings lives under the framework's `/settings`, outside this plugin's pages, so without it the operator had no way back; `safeBack` accepts only this plugin's own paths. *Superseded below.*
- **[2026-10-17] Trails and the way back are the framework's** (API 11, ADR-043): `Breadcrumbs`, `pluginSettingsLink` and `usePluginReturn` from `pluginHost/breadcrumbs`. Never validate a `back` path here -- the host checks it with the same rule that decides which routes the plugin may mount. The host renders the Settings trail; the Settings page draws none.

## Constraints

- **[2026-10-16] A Cost Management query covers at most a year**; history is twelve months.
- **[2026-10-16] Cost Management throttles per sign-in, not only per scope.** After a few refreshes, an enrollment nothing had touched answered 429. Never query Azure from a page view; only the sync does.
- **[2026-10-16] A refresh waits out throttling of up to a minute.** Each twelve-month query costs about twelve query units of the scope's budget, so a refresh's second query is routinely throttled 15-45 seconds on a large EA enrollment. A shorter inline limit made every first refresh fail.
- **[2026-10-16] Billing accounts are listed on API `2020-05-01`, never newer.** For a partner's sign-in on indirect EA, `2021-10-01` onwards list none of the enrollments (0 against 135, `includeAll` makes no difference). Cost Management, forecast and balances work on current versions at the same scope.
- **[2026-10-16] Import the chart wrapper from `echarts-for-react/esm/core`, never `lib/core`.** `lib/` is CommonJS; under the Vite dev server its default import is the module object and React fails with "Element type is invalid". The publish gate builds but never renders, so only opening the page catches it.
- **[2026-10-16] Through `az.cmd`, an `&` in a URL is eaten by cmd.** When probing Azure by hand, pass query parameters with `az rest --url-parameters`, not in `--url`.
- **[2026-10-16] A month is settled five days after it ends**; until then it is fetched again on refresh, after that never.
- **[2026-10-16] `az` must be on the backend's PATH and signed in as the operator.** A backend run as a service account would not see the operator's billing accounts.
- **[2026-10-17] The Consumption API pads its currency code** (`"USD  "`). Trim it before it reaches `Intl.NumberFormat`, which rejects it and falls back to raw digits.
- **[2026-10-17] Installing a backend change interrupts a running sync.** The plugin's backend loads only when the framework's backend reloads, and the reload stops the sync thread. Settled months survive, so start the sync again afterwards; a UI-only change needs just the frontend dev server restarted.
- **[2026-10-17] Right after a backend restart the vault index is empty.** Every Customer note reads as missing for a few seconds. Anything done once per run against notes must retry until it succeeds, never mark itself done on a failure.
- **[2026-10-17] Excel compares PivotTable items ignoring case.** A pivot cache holding "CommVault" and "Commvault" makes the whole workbook fail to open (`Workbooks.Open` fails, no repair offered). Fold every text field with `xlsx_pivot.fold_case` before writing a pivot's data. Check a generated pivot by opening it in Excel through COM; openpyxl will write a broken one without complaint.
- **[2026-10-17] Coverage is read from amortized meters; candidates from actual.** Under actual cost a reservation's usage costs nothing and its purchase lands in one month, so coverage needs `AmortizedCost`. On-demand costs the same either way, so steady candidates read the full actual history. Azure's `Unassigned` meter subcategory is a catch-all, never a candidate.
- **[2026-10-17] Savings are priced per VM series, not per size.** The meter detail names a series, so a series gets the average discount across its sizes in the pricing region, from the public Retail Prices API (`api-version=2023-01-01-preview` carries savings plan prices). A Windows meter saves on compute only. A savings Opportunity is created with no consumption plan, so it never adds to the pipeline forecast.
- **[2026-10-17] Cost by tag is one Cost Management query per tag key spelling.** Grouping takes a single `TagKey`, and customers spell one tag many ways (480 keys on one enrollment). So query only the spellings an enrollment has (its keys come from the Consumption tags API, which is not on the throttling budget), cap them per dimension, and keep the window short.
- **[2026-10-17] Every screen must survive the backend restarting under it.** An install or a framework change reloads the backend, and the plugin's routes answer 404 for a few seconds. A one-shot fetch that keeps its failure (Settings' billing accounts did) breaks the screen until a reload: retry, and say so.
- **[2026-10-17] A sync of everyone resumes, it does not restart.** Never-synced first, then oldest; an enrollment synced within `RESYNC_AFTER` (20 h) is skipped, consumption and tags alike. A named customer's sync always runs. Settled months were already never refetched -- the cost of a redo was the current month, forecast and tag queries per enrollment under throttling.
- **[2026-10-17] Never deep-copy an account entry to read a field.** `store.account()` round-trips the whole entry through JSON (months, meters, tags, Marketplace); on a 15 MB cache that is ~10 ms each. Status-only reads use `account_status()`.
- **[2026-10-18] Reading a MACC from a note is expensive, so it is cached (60 s).** Each Entities `commitment(stem)` scans the vault index; with every customer linked, an uncached listing cost 9-15 s. Anything that lists customers often must go through `CommitmentNotes`, never the Entities service directly.
- **[2026-10-18] Daily figures are fetched only on demand** (operator: no scheduled job). `entry["daily"]` holds last month and this one by day; a workload is new when it cost nothing last month and -- for a service or subscription -- in the three closed months before. Every new workload is flagged; the operator decides which is an opportunity.
- **[2026-10-18] A new sync stage must be shown by the banner before it ships.** `SyncControl` renders whatever `status.current` a stage sets; a stage without `first_month` crashed every customer page while it ran. Add the stage's flag to `SyncStatus.current` and a phase line in `SyncControl`.
- **[2026-10-18] A figure added up across enrollments must name the ones it lacks.** A refresh cut off by a backend restart leaves some enrollments without the data; summing only what is there understated ADNOC's last month by $1.9M with nothing on the page to say so. Report the missing enrollments with the figure.
- **[2026-10-18] A stuck sync is diagnosed from `Sync-Log.json`, not the status.** The status holds only the step in progress and is lost on restart; the log (`sync_log.SyncLog`) records steps, requests, pages, waits and errors per run, and marks a run still "running" at load as interrupted. A new sync entry point must call `log.begin` and finish through `_run_and_finish`, which calls `log.end`.
- **[2026-10-18] MACC burn and Core42 revenue are different measures.** The signed value always counts usage + Marketplace (less offers marked not eligible) − credits; no per-commitment switches. Core42 revenue is that burn less Marketplace from publishers other than Core42/G42 (`consumption_analysis.is_core42_publisher`), read from the month's Marketplace charges, never the balance's Marketplace total. Credits stay a filter on revenue. Other G42-group publishers such as Presight AI are NOT Core42 revenue (operator, 2026-10-18).
- **[2026-10-18] Refresh this month fetches from a marker.** Each enrollment's `daily.last_day` is the marker; a refresh asks again from `DAILY_REFETCH_DAYS` (= `SETTLING_DAYS`, 5) before it, keeps every earlier stored day, and drops days before last month's first. Never fetch only *after* the marker: Azure lags a day or two and revises recent days. A large enrollment's daily query pages 40+ times under throttling, so never refetch what cannot have changed.
- **[2026-10-18] The cache is one ~27 MB file: write it rarely.** A sync runs inside `store.holding_writes()`, so `save_account` reaches the file at most every `CACHE_WRITE_EVERY_SECONDS` (30 s) and on `flush()` (after each enrollment). Outside a sync every save is written at once, because callers and tests reread the file. The cache is compact JSON; the small settings files stay indented.
- **[2026-10-18] Nothing but a lost sign-in may stop a whole sync.** `BillingClient` retries `httpx.TransportError` (2, 10, 30 s) and then raises `AzureApiError(0, ...)`, which the sync records per window. Each enrollment runs through `ConsumptionSync._one_enrollment`, which records any other exception and continues; only `AzureSignInError` propagates.
- **[2026-10-18] An interrupted sync resumes on load.** `register` arms a timer (`RESUME_AFTER_SECONDS`, 20 s) that calls `ConsumptionSync.resume_interrupted`. That reads `SyncLog.interrupted_scope()` (the newest run, if a restart cut it off within `RESUME_WITHIN`, 12 h, whichever load closed it) and maps the scope back to its start call (`_start_scope`). A new scope format must be added there. The guard counts only interrupted runs with zero requests (`fruitless_in_a_row`), so a run that makes progress between frequent reloads keeps resuming.
- **[2026-10-18] A parent's affiliates either roll up into its MACC or signed their own** (`commitment.affiliates`: "roll up" default, "own"; note key `macc_affiliates`). With "own", only what burns the MACC narrows to the parent's own enrollments (`analyse(burn_merged=...)`, the portfolio's burn); totals and exports stay the group; allocations are None. Use `consumption_analysis.affiliates_roll_up`, never compare the string. Note writes go through `CommitmentNotes.write`, which sends only `COMMITMENT_FIELDS` the Entities service declares.
- **[2026-10-19] On screen and in exports it is "MACC consumed", never "burn".** The operator shows these pages to customers. Code identifiers (`burn_down`, `BurnDown`, `burn_rate_3m`) keep their names; only displayed text uses consumed / consumption rate.
- **[2026-10-21] The billing date is not on the default report.** `measure.billing_day` and `report_date` remain, with `DEFAULT_BILLING_DAY` = 1 (calendar months), and the UI sends none. A billing-date view only decided when a month closed, which read as "does nothing". The operator wants a separate Billing report with 5th-to-4th months across all history, which needs daily data for every month (see PLAN.md).
- **[2026-10-21] A report can show a subset of the group's enrollments** (`analysis(..., accounts=[...])`, query `accounts=a,b`). Totals, charts, breakdowns, forecast and export follow it. The MACC consumed never does: `_analysis` passes `burn_merged` (the full group, or the parent's own when affiliates are "own") whenever a subset is shown. The URL keeps the choice as `enrollments=<customer id>:<a>,<b>`, so it never applies to another customer.
- **[2026-10-21] Solution plays are a mapping, not a classification.** `solution_plays.DEFAULT_MAPPING` maps Cost Management's ServiceName to a play, and the operator's overrides in `Solution-Plays.json` win. An unknown service is Unassigned and listed in Settings. The one cross-play rule is GPU: `categories.detail` GPU meters move from the Virtual Machines service's play to AI & ML, capped at that service's cost. Plays are read from Cost Management actual cost (Marketplace in, credits not subtracted), as in Breakdown.
- **[2026-10-21] Cost Management omits Marketplace on EA enrollments.** Anything that totals spend by service (solution plays) must take Marketplace from the month's `measured.marketplace` (the invoice) when it is larger, as `solution_plays.split(..., marketplace=)` does. Otherwise EA Marketplace reads as near zero.
- **[2026-10-21] Cross-customer reports are pure modules plus one service method.** `growth`, `whitespace`, `marketplace_whitespace`, `hygiene` and `renewals` take merged months or cache entries and return rows; `ConsumptionService.*_across` and `renewals` only gather inputs. Thresholds live as module constants, and every page says them in plain words.
- **[2026-10-21] Every report page exports to Excel on the shared template.** Cross-customer workbooks live in `export_reports` and reuse `export_xlsx`'s helpers (`_new_sheet`, `_section`, `_table`, `_bar`/`_place`, the palette and formats), never their own styling. A new report adds a builder there and a key in `ConsumptionService.export_report`. Open the result in Excel through COM before release; openpyxl writes files Excel refuses.
- **[2026-10-22] Quota counts consumption above one shared baseline, net.** `quota.settings` (in `Quota.json`) holds the baseline start, the number of months, the fiscal year's first month, an optional quota period (`period_first`/`period_last`, e.g. H2 only) and the quota amount. The `fy_*` keys name the period in use. One baseline applies to every customer (operator's choice), and the default is the months before the fiscal year. The measure follows the report's Marketplace and credits filters. Forecast months use `forecasting.automatic`'s series; with no forecast, a month stands at the line. The quota is the seller's: never shown in Customer view.
- **[2026-10-23] Data export/import replaces whole files.** `data_transfer` zips every `DATA_FILES` entry with a manifest (format, version); import takes only basenames this version knows, checks each is JSON, writes them through `store.replace_files` and drops the in-memory cache. Two machines' syncs are never merged. A new data file joins the export by joining `DATA_FILES`; a file that must stay per-machine (the sync log) stays out of it. Import is refused while a sync runs, since the sync would write its own cache back over it.
- **[2026-10-23] Solutions are read from a subscription footprint, not the monthly cache.** The monthly sync drops the service x subscription pairing on purpose (size); `entry['footprint']` keeps it for the last `FOOTPRINT_MONTHS` closed months only, by service, meter subcategory and resource group, fetched in the tags sync and again only when another month closes. `solutions` matches patterns against it: signals are `service:<exact ServiceName>`, `meter:<substring>`, `name:<word>`; real ServiceNames come from the cache (e.g. Azure OpenAI is meter `Azure OpenAI` under service `Foundry Models`; Specialized Compute is AVS, not GPU). A pitch fires only when the missing signal is absent from the customer's whole estate. Seller-facing: never shown in Customer view.
- **[2026-10-23] Never drop a dimension Azure already answered with.** Splitting service x subscription into two maps to save space lost which service ran where, and getting it back meant refetching the whole history (operator: "a bad move"). Keep the joint breakdown a query returns (`months[m].actual.pairs`, `daily.pairs`); aggregate on read, not on write. A new kept field joins `months_to_fetch`'s completeness test so older months are fetched once more.
- **[2026-10-23] Solution patterns are read from the vault's Solution notes (operator's choice).** `SolutionNotes` reads every indexed note with `type: Solution` through `api.vault.entries()` and `read_section` (Pattern json block, Sizing table, Architecture mermaid), cached a minute; `solutions.DEFAULT_PATTERNS` applies only when the vault has none. The plugin never writes notes -- the Plugin API has no note write -- so the guide's content is written into the vault, not shipped. Templates `solution` and `playbook` ship in `templates/`. A new pattern field must be passed through `solutions.validated`, which rebuilds each pattern from known keys.
- **[2026-10-23] The plugin is shown as Azure Customer 360; its id stays `azure-cost-manager`.** The operator chose a display-only rename: the id is baked into routes, the data folder, the services Insight and Entities call, the repo and Marketplace history. Say "Azure Customer 360" in anything a person reads (labels, messages, file names); never rename the id, routes, `Azure-Cost-Manager/` data paths or service names without a migration.
- **[2026-10-23] Every name and chart drills, through one panel.** `Drill.tsx`: `useDrillState` keeps `drill=<kind>:<name>` in the URL; `DrillProvider` (in the customer report) lets any `DrillLink` or chart `onPick` open it; outside a report `DrillLink` takes `customerId` and links to `drillLink(...)`. A new screen that shows a service, subscription, play or month uses `DrillLink`, and a new chart passes `onPick`. `consumption_analysis.merge` carries `pairs`; `drill.analyse` is pure; Technology notes are matched by `technology_notes.ALIASES` when the billed name differs from the note's title.
- **[2026-10-23] Details open in a popup, never unfold in place (operator's rule).** Any drill-down or row detail uses `ui/Popup.tsx` (fixed to the window; Close, Escape, click outside); inside a table use `PopupRow`. The host forbids `react-dom`, so there is no portal. A new screen with per-row detail opens a popup, not an unfolding row.
- **[2026-10-23] The model explains; the plugin supplies every figure.** Anything Compass writes (the brief, and what follows it) is grounded on a facts dict the plugin computed (`brief.facts`), and the prompt forbids any other number. Output is kept with `brief.fingerprint(facts)` and rewritten only on asking; a changed fingerprint shows as stale. Compass is reached through `getattr(api, 'llm', None)` (optional under API 12, framework ADR-063): every LLM feature must work, and say why not, when it is absent.
- **[2026-10-23] Compass suggests; the rules decide.** A placement (`placement.py`) is stored apart from the rules' result and shown as Compass's, keyed by `<customer id>|<subscription>` with the fingerprint of what the subscription ran; it is asked again only when that changes. A proposed new solution becomes a Solution note the operator pastes into the vault -- the plugin never writes notes -- after which the rules place it without Compass.
- **[2026-10-23] A Compass feature is facts -> prompt -> checked answer, in that order.** `advisor.py` holds each feature's facts, prompt and check (pure); `advisor_service.Advisor` gathers facts from the existing reports and keeps answers in `compass.Answers` by fingerprint. A check drops anything about an unknown customer, block, report or product, and any money shown is recomputed from the plugin's own figures (sizing, bills) -- a model's number is never displayed. Failures map to 424 (no Compass) and 502 (Compass) via `routes._compass`.
- **[2026-10-23] Every Compass feature about a customer reads its memory.** `memory.CustomerMemory` (`service.memory`) holds what the seller told Compass; `brief_facts` carries it as `seller_says`, and explain, draft, size and actions hand it on. A new Compass feature that writes about a customer must take it too, and say in its prompt that it is fact that corrects guesses but never a report's figure.
- **[2026-10-23] Solution plays are amortized, and third-party VM licenses are Marketplace.** Every play split goes through `solution_plays.split_month` (amortized services and meters). 'Unassigned' in actual cost is commitment purchases (it is ~0 amortized), never Marketplace. 'Virtual Machine Licenses' mixes Microsoft licenses (Azure) with third-party software that the EA invoice also bills as Marketplace; `third_party_licenses` moves the part matching an invoiced offer by name (capped by the invoice Marketplace not shown as SaaS) so it is counted once.
- **[2026-10-24] A Compass output meant for the customer is never handed the seller's facts.** The savings report (`advisor.finops_facts(..., customer_view=True)`) gets only the customer's own FinOps findings. The MACC, pitches, quota, pipeline and `seller_says` go only to seller-facing features. Any new customer-facing Compass text must be built the same way.
- **[2026-10-24] Compass's text for the customer, and a Compass card, each come from one shared piece** (`ui/CompassText.tsx`). Text for the customer opens through `KeptTextButton` (kept, written on first open, copyable). A Compass plan card folds with `useRememberedFold(<storage key>)` and keeps its Ask button in the fold's title. A new feature reuses both rather than copying them.
- **[2026-10-24] A Compass prompt is persona + fixed task.** Who Compass is lives in `personas.py` (editable in Settings, kept in `Compass-Personas.json`) and is put ahead of each feature's system prompt by `personas.apply`; the task, `RULES` and the JSON shape a check reads stay in `advisor`/`brief`, never in a persona. A new Compass feature names its persona in `personas.FEATURES`, asks through `Advisor._ask(feature, ...)` and stamps through `_stamp(feature, ...)`, so a persona edit marks its answers stale.
- **[2026-10-24] A customer's industry is the Customer note's `industry` wikilink (or its parent's), read through `industry.IndustryContext`.** Never guessed: none set is said, with setting it recommended, and every feature works without it. Industry facts are handed with `INDUSTRY_RULE`; a business recommendation must still name a catalog solution, so its sizing stays the Solution note's.
- **[2026-10-24] The plugin writes notes of its own Templates when the seller asks, and only as new files.** The operator reversed "the plugin never writes notes" for industry use cases: Publish to vault (`use_cases.write_new`) files one beside its Industry note, never over an existing note, at `status: draft`. Notes of another plugin's Template (Opportunities) still go through that plugin's service. A note written for the vault is about the industry, never one customer: the customer part stays in the drill-down.
- **[2026-10-25] An opportunity's baseline is frozen once and never recomputed.** The pipeline review measures the team's impact against the natural trend before an opportunity could move anything. `pipeline_snapshot` freezes it the first time the opportunity is seen, fitted before it was opened or started consuming, whichever is earlier, and `estimated` when not fitted at the snapshot itself. Recomputing it later would let the trend absorb the very growth the team drove. Retaking a week replaces the snapshot, never a baseline.
